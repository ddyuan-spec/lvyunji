一、功能概述

登录注册是 App 进入的第一道关口。本期提供手机号 + 验证码登录，首次验证即自动注册；用户默认无登录密码，故不提供密码登录。进入 App 前需在登录页勾选同意《用户协议》《隐私政策》。

二、用户场景

  • 新用户：打开 App → 登录页 → 输手机号 + 验证码 → 自动注册并登录 → 进入首页
  • 老用户（原小程序）：用同一手机号验证码登录 → 识别为已有账号 → 直接进入
  • 协议：登录前需勾选协议，未勾选拦截

三、功能需求详情

3.1 登录页

  • 显示位置：App 冷启动后首屏（未登录态）
  • 内容：品牌区、手机号输入、验证码输入 + 获取按钮、登录按钮、协议勾选行、协议链接
  • 说明：本期仅验证码登录一种方式，不展示密码登录入口

3.2 手机号 + 验证码登录（含自动注册）

  • 前置条件：未登录
  • 操作步骤：

1. 输入 11 位手机号

2. 点击"获取验证码" → 60s 倒计时（参考 202607 PRD 支付验证码逻辑）

3. 输入验证码

4. 点击"登录"

  • 业务规则：
  • 手机号未注册 → 自动创建账号并登录（默认无密码）
  • 手机号已注册 → 直接登录
  • 校验 / 异常分支：
  • 手机号为空 → Toast「请输入手机号」
  • 格式非法 → Toast「请输入正确的手机号码」
  • 验证码为空 / 位数不对 → Toast「请输入正确的验证码」
  • 验证码错误 / 过期 → Toast「验证码错误或已过期」
  • 频繁获取 → 服务端频控 + 前端 60s 倒计时禁用

3.3 用户协议 / 隐私政策 勾选

  • 登录按钮前置勾选项：「已阅读并同意《用户协议》《隐私政策》」
  • 未勾选点击登录 → Toast「请先阅读并同意用户协议与隐私政策」
  • 协议正文由后台控制台「协议文档」维护并下发，本期不展开交互细节
  • 不强制冷启动弹窗

3.4 登出 / 注销（待确认）

  • 登出：我的 - 设置（是否一期待确认）
  • 注销：我的 - 设置 - 注销账号（关联隐私政策 4.4，是否一期待确认）

四、交互流程

[App 冷启动] → [登录页]
  → 输入手机号 → 点击获取验证码 → 60s 倒计时
  → 输入验证码 → 勾选协议 → 点击登录
  → 后端校验：手机号是否存在
        ├─ 不存在 → 自动注册 → 返回 token + isNewUser=true
        └─ 存在   → 直接登录 → 返回 token
  → 进入首页

五、数据 / 接口（参考）

  • 发送验证码：POST /api/sms/send（body: { phone }）— 复用 202607 PRD 支付验证码逻辑（60s 频控 + 服务端限制）
  • 验证码登录 / 注册：POST /api/auth/login-by-code（body: { phone, code }）→ 返回 token + 是否新用户
  • 注：具体接口字段以后端宋健提供为准

六、埋点（建议）

  • 登录页曝光、获取验证码点击、登录成功 / 失败、协议勾选、协议查看点击、新用户注册成功

七、验收标准

  • 新手机号验证码登录后自动注册并可进入首页
  • 已注册手机号可正常登录
  • 未勾选协议无法登录
  • 验证码 60s 倒计时、各类错误提示正确
  • 协议可点击查看

八、待确认项

1. 密码体系：用户默认无密码，一期不做密码登录；若后续需要，需先补「设置密码」功能（二期候选）

2. 微信授权登录：一期不做（App 微信授权需单独开放平台资质，与小程序 appid 不同主体）

3. 登出 / 注销 / 换绑手机号：是否纳入一期

4. 推荐人绑定（拉新）：App 这版是否保留（关联 kb/business-flow.md）

5. 老用户合并：原小程序用户用同手机号登录是否自动合并账号
