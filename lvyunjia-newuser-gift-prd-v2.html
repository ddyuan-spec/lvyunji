二、项目背景与目标

2.1 业务背景（痛点分析）

  • 拉新成本高、转化低：绿韵家 App 当前会员单价 ¥49.9/件礼包主要靠线下门店导流，缺少会员间主动分享机制，新人首单转化率 ⚠️ 待确认 @运营组（待 BI 给基线值）。
  • 既有实物礼包无水权益：原惠民补贴套餐包中已包含 5L 饮用水权益，但作为 SKU 子项不易单独追踪领取/过期状态，需独立化为水权益订单以便精细化提醒与统计。
  • 邀请码场景存在但口径混乱：当前 C 端「邀请码」FAB 入口与后台「生成邀请码」操作存在，但实物订单页面无邀请码字段、兑换订单与会员订单混合展示，导致运营难以区分「会员自己买的」与「会员分享给新人兑换的」。

2.2 项目目标

维度目标
业务目标① 建立会员拉新激励机制（邀请码分享）
② 沉淀独立水权益订单，支持精细化领取追踪
③ 后台可清晰区分「邀请码订单/兑换订单」，便于运营分析

③ 同一账号终身限兑 1 次，规则明确

三、业务流程与架构

3.1 业务流程图（双主流程 + 异常分支）

依据与基线说明：本图依据 C 端原型 newuser-gift-c-app.html（15 屏）与商家后台原型 lvyunjia-admin-merchant-hub.html（3 屏）逐屏梳理绘制，覆盖「会员购买邀请码」与「新人兑换礼包」两条全链路主流程及失败分支；图中每个节点均可在 §四 对应页面小节中追溯。 ⚠️ 本图为本次需求梳理阶段新产出，尚未与业务方完成基线确认；禁止在后续 PRD 修订中自行简化 / 重绘 / 修改本流程图，任何差异须报用户确认后再改。

Flow A - 会员购买邀请码并分享

会员打开 App 首页 → 点击悬浮「邀请码」FAB（仅初级会员及以上可见） → 进入激活码详情页（p_invite_detail） → 选数量（stepper 1-99） → 点立即购买 → 邀请码·确认订单（无地址） → 去支付 → 收银台（选支付方式） → 确认支付 → 购买成功 + 按数量生成邀请码写入「我的邀请码」+ 写入会员订单

Flow B - 新人/老用户凭邀请码兑换礼包

新用户打开 App 首页 → 点击悬浮「新人礼包」FAB（未激活时显示） → 进入礼包介绍页（p_gift_intro） → 点立即激活 → 选择/新增收货地址（p_address / p_address_edit） → 兑换·确认订单（p_confirm） → 点确认购买 → 弹出邀请码输入框（code-modal） → 输入邀请码（≥8 位 + 大小写 + 特殊符号） → 校验：码存在/未使用/未过期/本人未兑换过 → 核销成功 → 写入兑换订单 + 标记 _user.activated=true（隐藏新人礼包 FAB） + 系统按规则生成 5L×7 袋水权益订单

异常分支

异常触发产品处理
邀请码不存在code-modal 提交时后端校验失败Toast「邀请码无效，请核对后重新输入」
邀请码已被使用码状态=已使用Toast「该邀请码已被使用」
本人已兑换过_user.activated=true前置拦截：新人礼包 FAB 已隐藏，不可进入 Flow B
网络异常提交时网络失败Toast「网络异常，请稍后重试」；订单状态保持待提交
支付失败收银台返回失败Toast「支付失败」；订单状态置为待付款；引导「查看我的订单」重新支付
