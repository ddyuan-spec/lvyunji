绿韵家 App 重构规划

面向决策层 · 现状盘点 → App 规划 → 架构与后续规划

对象：老板 / 决策层 版本：v2.0（按"现状 → App 规划 → 架构与规划"三段式修订） 关键事实：

  • 绿韵家前身为 有享猫，现有 146 个页面（见 kb/page-catalog.md）。
  • App 与微信小程序并存：App 是全新主端，小程序继续承接存量与引流，长期双端共存。
  • 智联不是 AI：它是消息/信息功能（通知、提醒、会员资讯），与 AI 无关。
  • AI 唯一来源 = 泰小虎：App 一期只新增"健康知识问答 + 关联产品推品"，全部复用泰小虎，绿韵家不写 AI 后端。
  • 技术：现有 C 端 Vue2 升级 Vue3（先删冗余文件，再用 Codex 转译 C 端核心功能）。

一、当前用户在小程序能做什么

数据来源：kb/function-inventory.md、kb/page-catalog.md（146 页原貌）。以下为现状盘点。

能力板块用户现在能做的事
商城选购逛首页 / 新品 / 健康专区 / 惠民补贴；搜索、看榜单；看商品详情、评价；加入购物车；确认下单、选收货地址；收银台支付（微信 / 银行卡）
订单与售后查全部订单 / 订单详情 / 物流；申请售后、选服务类型、填退货物流；平台介入申诉
会员与权益购惠民套餐得等级；用积分、优惠券；看我的权益、兑换记录
水机 IoT（核心差异化）看网格 / 我的工作站；水机管理、接水记录；申请水机、预约；工作站活动核销
拉新获客绑定推荐人、得免拼机会；拼单、订单分享拉新
消息（智联）收通知 / 提醒 / 会员资讯——消息信息功能，非 AI
个人中心 / 登录资料、账号安全、实名、收藏、反馈；快捷 / 验证码登录、注销

本期不在重点的能力（保留但非一期核心）：直播、会员广场、店铺管理（商家端）。

二、APP 用户进来能做什么（含业务流程图）

2.1 规划能力（App 主端）

在现有小程序能力基础上，App 一期聚焦四块，并把 AI 囊括进来：

块用户进来能做什么
商城 / 下单升级后的选购、加购、下单、支付、订单 / 售后全流程（Vue3 重做）
拉新裂变绑定推荐人、免拼机会、拼单、订单分享，形成获客闭环
AI 健康问答（泰小虎）首页卡片 / 独立入口提问 → 泰小虎基于产品知识库作答 → 答案底部关联推荐绿韵家产品（推品）→ 一键进商品详情
水机 IoT / 会员 / 消息延续现有水机、会员权益、消息（智联）等能力

AI 边界说明：AI 仅指"健康知识问答 + 关联产品推品"，能力全部来自泰小虎；智联是消息信息功能，不算 AI。绿韵家只做前端交互层（入口 / 对话 UI / 结果展示 / 关联产品卡片），不重写 AI 后端。

三、架构图与后续规划

3.1 系统架构图

App 与小程序并存：App 为全新 Vue3 主端，小程序继续承接存量与引流。AI 能力（健康问答 / 推品）统一复用泰小虎，不重复建设。

3.2 后续规划（分阶段）

一期（本次重构）

  • App（Vue3）上线，与小程序并存；保留并升级：商城 / 下单、拉新、水机 IoT、会员权益、消息（智联）。
  • 新增 AI 健康问答板块（泰小虎复用，含关联产品推品）。
  • 后台按需新建：商品 / 订单、会员 / 权益、水机 / 工作站、收益结算、AI 知识库、基础管理。
  • 收益结算核心逻辑完整迁移（奖金 6 定时任务 + 水站分账 + 每月 1 号结算 + 元气系统数据导入，详见 kb/settlement-logic.md）。

二期（评估 / 后置）

  • 直播能力接入。
  • 会员广场、店铺管理（商家端）是否纳入评估。
  • 更多 AI 场景：智能导购、AI 售后助手（仍基于泰小虎）。
  • 小程序长期定位与双端协同策略持续打磨。

技术路线

  • Vue2 → Vue3：先删 C 端不需要的文件，再用 Codex 转译 C 端核心功能。
  • AI 全复用泰小虎，只加前端交互层；后台不整体重写，按 C 端流程反推需单独管理的模块。
