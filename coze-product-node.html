01接口速览（已实测）

三种 type 的返回形态不一样，这是最容易踩的坑，代码里已做归一化。

项值
请求方式POST · application/x-www-form-urlencoded
URLhttps://yxm-test-api.juhuanvip.com/api/apiWxStore/v2//coze/free/assistProduct（注意 v2//coze 是双斜杠，照抄）
请求头wxName: lym apiFrom: H5MALL accessToken: <token>
入参type 必填；userId 必填；productName 仅 type=2 用

type 取值与返回形态对照

type场景data 形态实测条数返回顺序
0帮我省Array<Object>3 条不稳定（两次请求一次升序一次降序）
1帮我选Array<Object>3 条不稳定
2按商品名查单个Object（不是数组）1 条—
三个实测发现的坑：
1. type=2 返回对象、0/1 返回数组 —— 代码里用 Array.isArray() 统一成数组，避免下游报错。
2. 后端返回顺序不能用 —— 同一 type 连续两次请求结果集和顺序都在变（疑似按用户行为动态推荐）。所以「省」的差额降序、「选」的打分降序必须在代码节点里自己排，不能信后端顺序。
3. 只用 productMainImg —— productCoverImg 实测恒为 null。

节点输入参数配置

    

      
参数名类型必填取值 / 来源

      
typeString是0 帮我省 / 1 帮我选 / 2 按商品名查单个。由上游意图识别节点给出

      
userIdString否当前用户 userId（App 透传）。不传时默认 1553843，仅便于调试，上线必须传真实值

      
productNameString否仅 type=2 时需要，用户问到的具体商品名

    


    
节点输出参数配置

    

      
参数名类型用途

      
productsArray<Object>商品数组，给下游节点 / 卡片组件直接取用

      
card_jsonString严格 JSON 字符串，前端解析后直接渲染卡片（结构见 04）

      
countNumber商品条数

      
successBoolean是否成功，失败时下游走兜底话术，不要让大模型编商品

      
errorString失败原因（超时 / code≠1 / 无数据）

      
summaryString给大模型写推荐文案的一句话素材，如「共 3 款商品，最高可省 ¥2109」

06待确认清单

    
以下 7 项需要后端 / 产品侧确认，其中 ①② 不解决会直接导致卡片显示异常。

    

      
#事项现状（实测）需要谁给

      

        ①
        商品图片完整 URL 前缀
        接口只返回相对路径 /common/2026/1/27/xxx.jpg；已试探 6 个候选域名均 404 / 无此域名，推测需要专门图片域名或 CDN
        后端
      

      

        ②
        生产环境 accessToken 来源
        文档给的是测试环境固定 token，硬编码会过期且泄露风险高
        后端（建议随 userId 由 App 网关透传，或提供 Coze 专用长期 token）
      

      

        ③
        score 分数量纲
        实测出现 20 / 60 / 100 / 150 / 205 / 230，不是 0–100，标签「AI评分 230」不符合用户直觉
        产品定口径（归一化 100 / 换算十分制 / 不展示分数，只展示理由）
      

      

        ④
        推荐结果混入测试数据
        实测结果里出现「【新人区】测试商品」「测试水卡模版 ¥9.9」，且 9.9 元商品差额为 0 却进了「帮我选」Top1
        后端过滤测试商品 / 加白名单
      

      

        ⑤
        卡片副标题 desc 来源
        接口无描述字段，当前留空；原型卡片上有卖点文案
        产品定：留空 / 大模型生成 / 后端补字段
      

      

        ⑥
        推荐是否可复现
        同一 type 连续两次请求，商品集合和顺序都不同
        后端确认是随机还是按行为动态；如需可复现需加缓存/种子
      

      

        ⑦
        生产域名
        当前为 yxm-test-api.juhuanvip.com 测试环境
        后端（上线切成正式域名）
      

    

    

      代码里已预留两个可改常量：IMG_BASE（图片域名前缀）和 ACCESS_TOKEN（token），确认后改这两行即可，其余逻辑不用动。
