二、项目背景与目标

2.1 业务背景

绿韵家现有直播模块主要承载实时直播内容，但缺乏体系化的录播/课程视频内容沉淀。为提升用户留存与赋能经销商/会员学习，需要新增「商学院」模块，后台上传课程视频，C端按分类浏览与播放。

2.2 项目目标

  • 业务目标：为会员提供可回看的课程体系，支持按栏目分类浏览，降低培训成本。
  • 用户目标：C端用户可快速找到学习视频并流畅观看；运营人员可低门槛上传、上下架视频。

2.3 衡量指标（KPI）

  • 视频播放量（PV）与播放完成率
  • 商学院页面人均停留时长
  • 视频上架时效：后台上传后 T+0 在C端可见

核心链路：后台内容生产 → 上架 → C端内容消费。本需求不涉及直播回放，仅处理后台上传的点播视频。

3.3 信息架构

  • 数据层：视频表（id、名称、栏目ID、封面URL、视频URL、时长、状态、上传人、上传时间、播放量）；栏目表（id、名称、排序、状态）。
  • 服务层：视频管理接口（增删改查、上下架）；C端视频列表/详情接口。
  • 前端层：C端商学院首页 + 播放页；后台视频列表 + 栏目管理 + 新增/编辑页。

3.4 状态机

状态枚举：已上架、已下架、已删除。所有状态转换均须满足状态守卫。

当前状态操作状态守卫目标状态说明
已上架下架当前状态=已上架已下架C端列表不可见，已播放用户不影响
已下架上架当前状态=已下架 且 视频文件/封面/栏目有效已上架C端列表可见
已下架删除当前状态=已下架 且 无进行中活动/无播放记录或已停止运营已删除软删除，保留数据用于统计

四、功能需求详情

4.1 C端 · 商学院首页 本期新增

需求影响范围：C端App、小程序、H5。涉及终端明细：绿韵家C端全端。

4.1.1 页面原型与交互示意

商学院首页

入口链路：我的 → 数商服务 → 商学院

4.1.2 界面与展示规则

  • 顶部标题固定显示「商学院」。
  • Banner位：运营可配置一张顶部Banner（跳链可配，暂不支持轮播）。
  • 分类Tab：横向排列，默认选中第一个栏目；栏目数据由后台「栏目管理」维护。
  • 视频卡片：封面（16:9）+ 播放按钮 + 视频时长 + 标题 + 播放量。
  • 列表加载：支持下拉刷新，上拉无限滚动加载。
  • 空态：当前分类无视频时显示「-暂无更多数据-」。
  • 不包含：免费/付费标签、多集/剧集、点赞/收藏/分享按钮。

4.1.3 业务逻辑与边界条件

  • 入口：用户从「我的」页面进入「数商服务」，在数商工具列表点击「商学院」进入首页。商学院不属于底部Tab，进入商学院页面后底部Tab保持高亮「我的」。
  • Tab切换：点击Tab后立即切换分类并重新加载对应视频列表，当前列表滚动位置重置。
  • 点击卡片：进入视频播放页，携带视频ID。
  • 未登录：可浏览列表，播放时按现有登录态拦截逻辑处理。

4.1.4 列表字段表

字段名称需求说明备注
封面取视频封面URL比例16:9，缺图显示默认占位图
标题视频名称最多显示2行，超出省略
时长视频时长，格式 mm:ss后台上传时录入
播放量累计播放次数单次播放计一次，不区分用户

4.1.5 数据来源

字段名称取值逻辑说明
栏目列表调用《栏目列表接口》status=1 的启用栏目，按sort升序
视频列表调用《C端视频列表接口》，参数 category_id + page + status=1

4.2 C端 · 视频播放页 本期新增

需求影响范围：C端App、小程序、H5。

4.2.1 页面原型与交互示意

4.2.2 界面与展示规则

  • 顶部返回按钮返回商学院首页。
  • 视频播放器：宽度撑满，16:9比例，支持播放/暂停、进度条拖动、音量、倍速（1.0x/1.25x/1.5x/2.0x）、全屏。
  • 播放页下方展示视频标题、时长、播放量。
  • 不包含：点赞、收藏、分享、评论、相关推荐。

4.2.3 业务逻辑与边界条件

  • 自动播放：进入页面后视频不自动播放，显示封面+播放按钮，点击后播放。
  • 播放统计：点击播放时上报播放量（前端去重：同一用户5分钟内重复播放只计一次）。
  • 退出/返回：退出播放页时暂停播放；横屏全屏后返回保持当前进度。
  • 异常态：视频加载失败时Toast提示「视频加载失败，请稍后重试」。

4.3.1 页面原型与交互示意

4.3.2 界面与展示规则

  • 列表字段：视频ID、视频名称、视频封面、视频栏目、状态、视频时长、上传时间、操作。

4.3.9 新增/编辑视频功能

  • 功能说明：运营上传视频文件并填写基础信息后保存，生成视频记录。
  • 显示位置：独立页面（非Modal），路径：商学院管理 > 视频管理 > 添加视频。
  • 前置条件：用户有视频管理权限；栏目表中至少存在一个启用栏目。
  • 逐步操作逻辑：
    1. 用户点击「添加视频」进入表单页。
    2. 填写视频名称、选择栏目、上传视频文件、填写时长、上传封面、选择状态、填写简介。
    3. 点击「保存」：校验必填项与格式 → 通过则保存并返回列表页，Toast「保存成功」；失败则聚焦首个错误项并提示。

4.4 后台 · 栏目管理 本期新增

需求影响范围：绿韵家管理后台。

4.4.1 界面与展示规则

  • 列表字段：栏目ID、栏目名称、排序、状态、操作。
  • 操作：编辑、删除。
  • 状态：启用（绿色）/ 禁用（红色），禁用的栏目不在C端Tab显示。

4.4.2 业务逻辑与边界条件

  • 栏目名称唯一，不可重复。
  • 删除栏目前需校验该栏目下无视频，否则提示「该栏目下存在视频，不可删除」。
  • 排序数值越小越靠前。

五、非功能性需求

5.1 性能

  • 视频列表首屏加载 ≤ 1.5s。
  • 视频播放首帧时间 ≤ 2s（网络正常）。
  • 后台列表页支持分页，默认10条/页。

5.2 安全

  • 视频URL需做防盗链或时效签名校验（与现有点播资源一致）。
  • 后台操作需校验管理员权限。

5.3 兼容性

  • C端支持iOS 12+ / Android 8+ / 微信内置浏览器。
  • 后台支持Chrome/Edge最新2个主版本。

六、验收标准

  1. AC1：运营在后台新增一个视频并上架后，C端对应分类Tab下30秒内可见该视频。
  2. AC2：C端用户点击视频卡片进入播放页，可正常播放/暂停、拖动进度、切换倍速。
  3. AC3：后台对已上架视频执行下架操作后，C端列表立即不再展示该视频，已播放用户不受影响。
  4. AC4：后台删除已下架视频后，数据库状态标记为删除，C端与列表均不可见。
  5. AC5：视频名称/栏目/状态查询条件可正确过滤列表数据。

七、关键边界设计检查清单

  • 网络异常：C端列表加载失败时显示「网络异常，点击重试」。
  • 空状态：分类无视频、搜索无结果均显示空态。
  • 权限：后台视频管理仅开放给运营/管理员角色。
  • 并发：同一视频多人同时播放不影响状态。
  • 数据一致性：视频上下架状态变更后，C端列表缓存刷新策略需保证最终一致。
