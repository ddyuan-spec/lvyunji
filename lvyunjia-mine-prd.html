二、项目背景与目标

2.1 业务背景

绿韵家小程序当前「我的」页面存在以下问题需优化：

  1. 分享模块陈旧：现有分享入口的弹窗样式和二维码逻辑已不匹配当前运营需求，需参照新版分享弹窗（含新人专享权益展示 + 海报保存能力）重新设计。
  2. 服务入口冗余：「我的服务」区域包含12个入口，其中排行榜、优惠券、收藏、直播广场4个入口与当前业务阶段不符或已有更优承载位置，需精简。
  3. 推荐商品未标准化：「我的」页底部推荐商品区域的算法规则未明确，需与首页推荐逻辑统一。

2.2 项目目标

目标维度具体指标/描述优先级
分享转化提升通过新版分享弹窗（新人专享视觉 + 海报保存）提升用户分享意愿和邀请注册率P0
页面精简「我的服务」从12个入口缩减至8个，降低用户认知负荷P0
体验一致性推荐商品算法与首页完全一致，避免用户感知差异P1

三、业务流程与架构

3.1 页面信息架构

改版后「我的」页面自上而下由以下模块组成：

  1. 个人信息区 — 头像、昵称、标签（分享达人/首庺）、账号 → 跳转个人信息页
  2. 订单信息区 — 待支付 / 待发货待销 / 待收货 / 待评价 / 退换售后 → 各状态订单列表
  3. 分享邀请区 — 「邀请好友·福利多多」卡片 → 点击弹出分享弹窗
  4. 我的服务区 — 网格 / 我的积分 / 收货地址 / 联系客服 / 意见反馈 / 代注册 / 工业游 / 公司资质（共8个）
  5. 推荐商品区 — 商品卡片瀑布流（2列），算法同首页

3.2 分享弹窗交互流程

  1. 用户在「我的」页面点击「邀请好友·福利多多」卡片区域
  2. 弹出分享弹窗（Modal 居中遮罩），展示：
    • 顶部：新人专享权益宣传图（9.9元解锁三重福利 + 手机mock + 福利标签）
    • 中部左侧：分享人信息（头像 + 昵称，取当前登录用户）
    • 中部右侧：二维码（根据终端类型区分生成，见 §4.4.2）
    • 底部：绿韵家品牌标识 + 长按二维码提示文案
    • 最底部：「保存海报」按钮（将弹窗内容合成为一张图片保存到本地）
  3. 用户可点击遮罩关闭弹窗，或点击「保存海报」保存后自动关闭

注：本节为页面级流程概述，详细字段规则见 §四 功能需求详情。本需求不涉及商家端后台、火山SaaS等范围外系统。

二、二维码生成逻辑（核心改动）

本期核心变更：分享弹窗中的二维码不再统一使用小程序码，而是根据当前运行终端分别生成不同类型的二维码：

运行终端二维码类型生成方式扫码结果是否带推荐关系
App / H5App 下载或唤起链接二维码后端生成包含 invite_code 参数的短链 → 转二维码图片微信扫码：打开 App 下载引导页（H5）；已安装用户：直接唤起 App 并落地首页，同时绑定推荐关系是
微信小程序小程序码（WXACode）调用微信 wxacode.getUnlimited 接口，scene 参数带入当前用户 invite_code扫码进入小程序首页，启动时读取 scene 参数绑定推荐关系是
实现要点：
  • 前端需能判断当前运行环境（navigator.userAgent 或 wx.getSystemInfo）来决定请求哪种二维码。
  • 二维码 API 由后端统一提供：GET /api/share/qrcode?terminal={app|mini}&invite_code={code}，返回 base64 图片或图片 URL。
  • invite_code 取当前登录用户的邀请码字段（取《用户表》.invite_code）。
  • 推荐关系绑定逻辑沿用现有邀请注册流程，本期不改造绑定本身。

五、「保存海报」按钮逐步操作逻辑

  1. 用户点击「保存海报」按钮
  2. 前端使用 canvas 将弹窗 DOM 渲染为图片（html2canvas 或原生 canvas 绘制）
  3. 调用系统相册写入权限请求
    • 正常分支：用户允许 → 写入相册成功 → Toast「海报已保存到相册」(1.5s) → 弹窗关闭
    • 异常分支1：用户拒绝 → 弹窗 Toast「保存失败，请在设置中允许相册权限」(2s) → 弹窗保持不关闭
    • 异常分支2：合成图片失败（DOM 过大/跨域资源）→ Toast「海报生成失败，请重试」(2s)
