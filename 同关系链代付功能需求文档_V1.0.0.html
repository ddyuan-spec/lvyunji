二、需求背景

当前绿韵家电商平台中，老会员（有 wallet 余额）无法直接为关系链内的新会员代付订单，新会员需自行完成支付，流程不够便捷。

本次新增「同关系链代付功能」，实现以下目标： 1. 订单账号（新会员）下单后，可发起代付请求，指定关系链内的老会员（支付账号）代为支付； 2. 支付账号收到代付请求后，可在 App 内完成确认并支付，支付规则为 70% 电子钱包 + 30% 储值钱包； 3. 支付完成后，订单在两端正常流转：订单账号可查看发货/收货状态，支付账号仅展示代付记录无操作权限； 4. 代付请求通过「智连 · 交易消息」推送，支付账号可点击消息直接跳转至对应代付订单详情。

三、原型地址

交互原型（HTML）：https://ddyuan-spec.github.io/lvyunji/proxy-payment-prototype.html

原型包含 11 个页面，覆盖订单账号和支付账号的完整交互链路。

五、需求说明

5.1 状态流转图

代付请求状态流转：

[待确认] ── 支付账号点击"立即代付" → [支付中] ── 支付成功 → [已完成]
    │
    └── 订单账号取消代付请求 → [已取消]

订单状态流转（支付完成后）：

[已支付·待发货] → [待收货] → [已完成]

字段/功能 需求说明 备注

5.3 订单在两端的状态同步

场景 订单账号视角 支付账号视角
代付请求已发起，待支付账号确认 订单状态：待付款（代付中）；可取消代付请求 智连消息：待处理；订单列表：待付款
支付账号已支付 订单状态：已支付·待发货；可查看物流 订单状态：已完成·代付(已完成)；仅展示无操作
商家发货 订单状态：待收货；可确认收货 订单状态：待收货（仅展示）；无操作按钮
订单账号确认收货 订单状态：已完成 订单状态：已完成（仅展示）

支付账号视角订单操作权限： - 代付请求「待付款」状态：支持「立即代付」操作； - 代付完成后：订单仅展示，无任何操作按钮（联系客服除外）； - 标识：订单详情页顶部展示「🤝 代付订单」标签，区别于普通订单。

5.4 权限说明

角色 权限说明
订单账号（新会员） 可发起代付请求、取消代付请求、查看订单流转状态
支付账号（老会员） 可查看代付请求、完成代付支付、查看代付记录（仅展示）
关系链限制 仅同关系链内的老会员可被指定为代付人，跨关系链不可代付

5.5 接口说明（待后端补充）

以下接口为预估，需与后端确认具体入参/出参。

接口名称 接口说明 备注
校验关系链 传入订单账号ID + 输入手机号，返回是否在关系链内及关系类型（上级/平级/下级）
发起代付请求 生成代付请求记录，推送智连消息至支付账号
查询代付请求列表 支付账号查询待处理/已完成的代付请求
确认代付支付 支付账号确认代付，按 70%/30% 比例从两个钱包扣款
取消代付请求 订单账号取消代付请求，恢复订单为待支付状态
查询订单状态 两端查询订单最新状态

5.6 数据字段说明

代付请求表（预估）：

字段名称 说明 类型
代付请求ID 唯一标识 BigInt
订单号 关联的订单编号 Varchar
订单账号ID 发起代付的用户ID BigInt
订单账号名称 发起代付的用户名称 Varchar
支付账号ID 被指定代付的用户ID BigInt
支付账号名称 被指定代付的用户名称 Varchar
代付金额 需代付的金额 Decimal(10,2)
钱包扣款比例 电子钱包比例%/储值钱包比例%（当前固定70/30） Varchar
状态 待确认 / 支付中 / 已完成 / 已取消 Enum
创建时间 代付请求创建时间 Datetime
支付时间 代付完成时间 Datetime

6.2 待确认事项

  1. 支付比例规则：当前原型固定为 70% 电子钱包 + 30% 储值钱包，是否需要在后台支持配置？
  2. 代付请求有效期：代付请求发起后，支付账号多久内需处理？超时是否自动取消？
  3. 智连消息推送：消息推送的实际触发节点和文案是否需要单独评审？
  4. 钱包余额不足：单一钱包余额不足时的扣款策略，需与财务/后端确认。
  5. 关系链校验：校验接口的数据来源和系统对接方式，需与关系链模块负责人确认。
